# Pruebas automatizadas

Tipos: `TransactionCase` para lógica de modelos (cada prueba en una transacción que se revierte), `HttpCase` para controladores y recorridos del cliente web (`start_tour`), pruebas de rendimiento con conteo de consultas (`assertQueryCount`), `Form` de `odoo.tests` para simular formularios y `onchange`. Etiquetas: `@tagged('post_install', '-at_install')` para pruebas que requieren todos los módulos instalados; etiquetas propias por módulo. Ejecución: `odoo-bin -d base_pruebas -i modulo --test-enable --stop-after-init` o `--test-tags /modulo` sobre una base con datos de demostración; en Odoo.sh las pruebas corren en cada compilación si están activas; en integración continua con contenedores y PostgreSQL de servicio. Contenido mínimo: creación y validación de registros, restricciones, cálculos, permisos por grupo (prueba con usuario sin privilegios), flujos principales de punta a punta, un recorrido del cliente web cuando hay vistas o componentes propios. Datos de prueba: creados en `setUpClass`, sin depender de datos de demostración de otros módulos salvo los estándar; empresas y monedas explícitas en pruebas multiempresa. Cobertura: medir con `coverage` y fijar un piso por módulo; las pruebas que fallan por fechas del sistema se congelan con `freezegun`. Criterio senior: la prueba que vale es la que reproduce el error que un cliente reportó; cada corrección entra con su prueba.
