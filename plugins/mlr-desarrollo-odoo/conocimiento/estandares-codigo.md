# Estándares de código (OCA y Odoo)

Estructura: `__init__.py`, `__manifest__.py` con `name`, `version` (versión de Odoo más tres dígitos propios, por ejemplo 19.0.1.0.0), `summary`, `author`, `website`, `license`, `category`, `depends`, `data`, `demo`, `assets`, `installable`, `application`, `auto_install`, `development_status` y `maintainers` en módulos OCA; carpetas `models`, `views`, `security`, `data`, `demo`, `wizards`, `report`, `controllers`, `static` (`description` con `icon.png` e `index.html`, `src` para OWL), `tests`, `i18n`, `readme` con fragmentos (`DESCRIPTION.md`, `CONFIGURE.md`, `USAGE.md`, `CONTRIBUTORS.md`, `ROADMAP.md`). Nombres: módulo en minúsculas con guiones bajos y prefijo por dominio; modelos `dominio.nombre`; identificadores externos `modelo_nombre_view_form`, `modelo_nombre_action`, `modelo_nombre_menu`, `modelo_nombre_rule`; archivos XML por modelo. Python: imports ordenados (estándar, terceros, Odoo), `from odoo import api, fields, models, _`; campos con `string` solo cuando no se deduce; cálculos con `@api.depends` completos y `store` consciente; `ondelete` explícito en relaciones; `_check_company_auto` en modelos multiempresa; sin lógica en `write` que pueda ir en cálculos; errores con `UserError` y `ValidationError` traducidos; sin `print`; registro con `_logger`. Seguridad: reglas de acceso por grupo en CSV, reglas de registro para multiempresa y propiedad, controladores con `auth` explícito y CSRF; `sudo()` solo para operaciones que el usuario no debería poder hacer directamente y nunca para esquivar reglas sin razón documentada; consultas SQL parametrizadas y preferentemente con el ORM. Vistas: herencia mínima con `xpath` precisos, `invisible` y `readonly` con expresiones, sin duplicar vistas estándar completas. Calidad: `pre-commit` con `pylint-odoo`, `flake8`, `black`, `isort`, `prettier` para XML; pruebas con cobertura razonable; registro de cambios por versión; README generado desde los fragmentos. Internacionalización: `i18n/es_MX.po` y `.pot` actualizados; cadenas visibles traducibles. Actualización segura: módulos que no modifican el núcleo, migraciones en `migrations/<versión>/pre-` y `post-migrate.py` cuando cambian datos.
