# Odoo Online (SaaS): lo que se puede y lo que no

Odoo Online es la nube gestionada de Odoo con actualización automática de versión y sin acceso al servidor: no se instalan módulos de terceros ni propios, no hay acceso al sistema de archivos ni a PostgreSQL, no hay shell. Lo que sí se puede: toda la configuración estándar; Studio (campos, vistas, automatizaciones, reportes) con los costos de mantenimiento que implica; acciones de servidor y automatizaciones con código Python en entorno restringido, que permiten lógica razonable e incluso operaciones directas de base de datos puntuales y controladas (la práctica de la firma es preferirlas a Studio y crear campos y vistas heredadas por API con un prefijo técnico propio); importación por plantillas; API externa sujeta al plan contratado (verificar en la documentación vigente qué planes la incluyen); respaldos descargables desde el administrador de bases; base de pruebas duplicada neutralizada desde el administrador; dominios propios; correo saliente propio. Lo que cambia la cotización: no hay desarrollo de módulos, así que cualquier brecha se resuelve con configuración, Studio o acciones de servidor, o se declara fuera de alcance; las actualizaciones de versión las hace Odoo y los campos y automatizaciones hechos a mano deben revisarse tras cada una; el soporte de la plataforma lo da Odoo y el del uso lo da el partner. Riesgos frecuentes: cambios hechos con SQL desde acciones de servidor sin registro, dependencias de Studio que rompen al actualizar, límites de usuarios y aplicaciones del plan, bases de prueba que vencen. Cuando el cliente necesita módulos propios o de terceros, la ruta es Odoo.sh o servidor propio, y esa decisión la toma el agente de arquitectura de infraestructura.
