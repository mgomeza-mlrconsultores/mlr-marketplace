# Diagramas: normas vigentes y criterios de diseño

Normas: BPMN 2.0 para procesos de negocio (piscinas por organización, carriles por rol, eventos de inicio, intermedios y fin, compuertas exclusivas, paralelas e inclusivas, tareas con tipo, flujos de secuencia y de mensaje; un proceso por diagrama y subprocesos para el detalle); UML 2.5 para estructura y comportamiento técnico (casos de uso, clases, secuencia, actividades, estados, despliegue); modelo C4 para arquitectura de software en cuatro niveles (contexto, contenedores, componentes, código) con notación simple y leyenda; ArchiMate 3 para arquitectura empresarial cuando el cliente la usa; diagramas de flujo con símbolos de ISO 5807 para procedimientos sencillos; entidad relación con notación pata de gallo para datos; DMN para reglas de decisión complejas. En consultoría Odoo los más útiles son BPMN para el proceso del cliente (situación actual y futura), C4 nivel contexto y contenedores para integraciones, secuencia para intercambios con PAC, bancos o APIs, y entidad relación simplificado para modelos personalizados.

Herramientas: Mermaid (flujo, secuencia, clases, entidad relación, Gantt, C4) para diagramas que viven en el repositorio y se renderizan en documentos; PlantUML para UML completo; draw.io para diagramas editables por el cliente; Excalidraw para bocetos de taller. El archivo fuente se guarda siempre junto al render.

Criterios de diseño (práctica actual de experiencia de usuario aplicada a diagramas): un mensaje por diagrama y título que lo dice; lectura de izquierda a derecha o de arriba abajo sin cruces de líneas; entre cinco y nueve elementos por vista y subdiagramas para el detalle; paleta corta con colores semánticos consistentes (estado actual, estado futuro, sistema, persona, riesgo) y contraste suficiente para imprimir en blanco y negro y para accesibilidad (WCAG 2.2 AA); tipografía legible al tamaño de impresión; leyenda cuando hay más de dos colores o símbolos; versión, fecha y autor en el pie; nombres de pasos con verbo e idénticos a los que usa el cliente y a las funcionalidades de Odoo; carriles por rol real, no por departamento genérico; nada decorativo. Revisión: el diagrama se valida con el dueño del proceso leyendo en voz alta cada paso; cada diferencia se corrige en el fuente.
